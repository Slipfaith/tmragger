# tmragger

Инструмент для подготовки TMX-файлов трансляционной памяти к использованию в RAG-системах.

## Что делает

Читает `.tmx`-файл, анализирует каждый TU (translation unit) и предлагает набор правок:

- **Сплит сегментов** — делит TU на несколько, если source и target содержат несколько предложений и выравниваются корректно
- **Очистка пробелов** — убирает двойные пробелы и пробелы по краям
- **Переносы строк** — схлопывает переносы строк и табы внутри сегмента в один пробел; обрабатывает как настоящие управляющие символы, так и литеральные последовательности `\t`, `\n`, `\r` (текст «бэкслэш+буква»), которые оставляют некоторые конвертеры
- **Удаление служебной разметки** — inline-теги, игровой markup (`^{...}^`, `$m(...|...)`), `%...%`-токены
- **Удаление мусорных TU** — пустые, числовые, декоративные сегменты
- **Удаление дублей TU** — убирает повторяющиеся пары (source, target), оставляя первое вхождение
- **Диагностика WARN** — помечает подозрительные TU (разница длины, несовпадение языка, идентичные src/tgt) без удаления
- **Codex verification** *(опционально)* — проверяет решения о сплите через Codex CLI (`gpt-6-luna`, reasoning effort `medium`)

## Рабочий процесс

Обработка двухфазная: сначала приложение строит **план** (список предложений), затем пользователь просматривает его в диалоге ревью и запускает **применение** только принятых правок.

```
Файлы → [Plan] → Ревью предложений → [Apply] → Готовый TMX + отчёты
```

## Запуск

### GUI

```bash
python main.py
```

Перетащите `.tmx`-файлы в окно или нажмите кнопку добавления. Настройте этапы в панели слева, нажмите **Run**. Результаты каждого файла сохраняются в папку `output` рядом с ним.

### CLI

```bash
python main.py --cli --input file.tmx --output-dir ./output
```

Основные флаги:

| Флаг | Описание |
|---|---|
| `--input <path...>` | Один или несколько входных TMX |
| `--output-dir <dir>` | Директория для результатов |
| `--no-split` | Отключить сплит |
| `--split-line-breaks` | Делить также по одиночным переносам строк: пункты списков, шаги «1. …», строки после заголовка (в GUI — чекбокс под «Сплит сегментов») |
| `--no-cleanup-spaces` | Отключить очистку пробелов |
| `--no-cleanup-garbage` | Отключить удаление мусорных TU |
| `--no-cleanup-warnings` | Отключить диагностику WARN |
| `--verify-codex` | Включить проверку сплита через Codex CLI (старый алиас `--verify-gemini`) |
| `--codex-model <name>` | Модель Codex (по умолчанию `gpt-6-luna`, или `CODEX_MODEL` env) |
| `--codex-effort <low\|medium\|high>` | Reasoning effort (по умолчанию `medium`, или `CODEX_REASONING_EFFORT` env) |
| `--dry-run` | Анализ без записи файла |
| `--report-dir <dir>` | Директория для JSON-отчётов |
| `--html-report-dir <dir>` | Директория для HTML diff-отчётов |
| `--xlsx-report-dir <dir>` | Директория для XLSX-отчётов |

## Отчёты

После обработки отчёты сохраняются в `output/` рядом с каждым исходным файлом:

- **JSON** — машиночитаемый лог всех правок и статистика
- **HTML** — визуальный diff: было / стало для каждого TU
- **XLSX** — многолистовой отчёт: сводка, сплиты, очистка, предупреждения

## Codex verification

Включается чекбоксом в GUI или флагом `--verify-codex` в CLI. API-ключ не нужен: используется авторизация Codex (`codex login`). Модель и effort меняются в GUI через **Инструменты → Настройки Codex…**.

Каждая проверка — отдельный вызов `codex exec --json` в пустой read-only папке. Бинарь ищется так: `CODEX_BIN` env → последний `codex.exe` из desktop-приложения Codex (`%LOCALAPPDATA%\OpenAI\Codex\bin`) → `codex` из PATH. Старый npm-`codex` может не знать модель `gpt-6-luna` — тогда обновите его или задайте `CODEX_BIN`.

При включении каждый кандидат на сплит отправляется в Codex, который возвращает вердикт `OK / WARN / FAIL` и уровень уверенности. Решения кэшируются внутри прогона (одинаковые кандидаты проверяются один раз) и могут сохраняться между прогонами (`--gemini-cache-file`).

**Пакетная проверка.** Кандидаты на сплит не отправляются по одному: они складываются в очередь и уходят в Codex пачками по 25 (`--codex-batch-size` / `CODEX_BATCH_SIZE`, `0` — по одному), до 4 пачек параллельно (`GEMINI_MAX_PARALLEL`). Одинаковые кандидаты в очереди отправляются один раз. По каждому кандидату Codex возвращает `OK`, `FIX` (исправленные точки разреза) или `FAIL` (не делить).

Исправление `FIX` принимается только если каждая часть — дословный кусок исходного сегмента, части идут по порядку, покрывают весь текст (между ними — только пробелы) и не режут теги. Любое изменение текста (особенно перевода в таргете) — и исправление отклоняется, TU остаётся нетронутым. Исключение: если Codex разрезал там же, где сплиттер, и поменял только пунктуацию (например, «.» → «!» в переводе), правки текста отбрасываются, а сплит применяется в исходном виде. В XLSX/TMX такие сплиты помечены вердиктом `WARN` и сводкой «Split fixed by Codex».

Дублирующиеся TU при включённом удалении дублей пропускаются до проверки Codex — это снижает количество вызовов.
